# Развёртывание стека Laravel 13 и Vue 3

## Введение

В проекте Laravel 13 обслуживает Vue SPA и API. Vite собирает фронтенд, Vue Router 4 переключает страницы, Pinia хранит данные текущего пользователя, а Axios отправляет запросы. Fortify обрабатывает регистрацию, вход, выход и сброс пароля. Sanctum определяет пользователя по сессионной cookie, после чего Laravel проверяет его права через политики.

Если вы запускаете этот репозиторий, начните с шага 1, затем перейдите к шагу 6. Шаги 2–5 показывают, как стек подключён и как повторить эту интеграцию в другом приложении на Laravel 13.

## 1. Установить зависимости и подготовить окружение

**Команда/действие**

В корне репозитория выполните:

```bash
composer install
npm ci
test -f .env || cp .env.example .env
```

В `.env` укажите фактический адрес приложения в `APP_URL` и проверьте настройки базы данных. Для локального сайта в Flock используется `APP_URL=https://for-flock.test`.

Если `APP_KEY` в новом `.env` пустой, выполните:

```bash
php artisan key:generate --no-interaction
```

**Физический смысл**

Composer устанавливает PHP-пакеты в `vendor/`, npm устанавливает JS-пакеты в `node_modules/`. Laravel загружает параметры окружения из `.env` и использует ключ приложения для шифрования cookie.

**Краткое пояснение**

Команды установки берут версии из `composer.lock` и `package-lock.json`. Текущий проект использует PHP 8.5 и Node.js 26 в Flock.

**Условия/ограничения**

Сохраняйте действующий `APP_KEY` при повторном развёртывании. Для PostgreSQL нужна существующая база и доступ к ней. Для SQLite проверьте, что файл базы существует и доступен на запись.

## 2. Добавить пакеты при подключении стека к другому приложению

**Команда/действие**

В приложении на Laravel 13, где этих пакетов ещё нет, выполните:

```bash
composer require 'laravel/fortify:^1.42' 'laravel/sanctum:^4.4' --no-interaction
npm install 'vue@^3' 'vue-router@^4' 'pinia@^4' 'axios@^1'
npm install --save-dev 'vite@^8' '@vitejs/plugin-vue@^6' 'laravel-vite-plugin@^3'
```

**Физический смысл**

Composer и npm добавляют пакеты в манифесты и записывают разрешённые версии в lock-файлы.

**Краткое пояснение**

Fortify и Sanctum подключаются на стороне Laravel. Плагин Vue для Vite компилирует компоненты `.vue`, а Laravel Vite Plugin связывает точки входа с Blade.

**Условия/ограничения**

В этом репозитории пакеты уже добавлены. При переносе интеграции проверьте ограничения версий в целевом проекте.

## 3. Подключить Vue SPA

**Команда/действие**

1. В [vite.config.js](vite.config.js) подключите `@vitejs/plugin-vue` и укажите точки входа `resources/css/app.css` и `resources/js/app.js`.
2. В [app.blade.php](resources/views/app.blade.php) подключите эти файлы через `@vite` и добавьте элемент `#app`.
3. В [app.js](resources/js/app.js) создайте Vue-приложение, подключите Pinia перед Vue Router и смонтируйте приложение в `#app`. Используйте [router.js](resources/js/router.js) и [auth.js](resources/js/auth.js) как примеры маршрутизации и хранения состояния сессии.
4. В [routes/web.php](routes/web.php) направьте GET-запросы для страниц SPA на Blade-шаблон.

**Физический смысл**

При прямом переходе или обновлении страницы Laravel отдаёт HTML с точками входа Vite. После загрузки Vue Router выбирает компонент по адресу, а Pinia хранит профиль, полученный из API.

**Краткое пояснение**

Vue Router использует `createWebHistory()`. Поэтому Laravel должен обслуживать и прямые переходы на адреса вроде `/dashboard` и `/reset-password/{token}`.

## 4. Настроить Fortify и Sanctum

**Команда/действие**

1. В [config/fortify.php](config/fortify.php) установите `views => false` и включите регистрацию и сброс пароля.
2. Зарегистрируйте [FortifyServiceProvider](app/Providers/FortifyServiceProvider.php) в [bootstrap/providers.php](bootstrap/providers.php). В провайдере привяжите [действия регистрации и сброса пароля](app/Actions/Fortify) и настройте ограничение попыток входа.
3. Добавьте именованный GET-маршрут `password.reset` на `/reset-password/{token}` в [routes/web.php](routes/web.php). Laravel использует его для формирования ссылки в письме.
4. Подключите `routes/api.php` и вызовите `$middleware->statefulApi()` в [bootstrap/app.php](bootstrap/app.php). Добавьте `auth:sanctum` к защищённым маршрутам.
5. В [http.js](resources/js/http.js) отправляйте `Accept: application/json` и перед запросом, который меняет состояние, вызывайте `GET /sanctum/csrf-cookie`. Затем отправляйте форму на нужный POST-адрес Fortify.

**Физический смысл**

Laravel выдаёт CSRF-cookie, а Axios при запросе на тот же адрес передаёт её значение в заголовке `X-XSRF-TOKEN`. После успешного входа браузер отправляет сессионную cookie вместе с запросами к API, и Sanctum восстанавливает пользователя из сессии.

**Краткое пояснение**

Fortify предоставляет `POST /register`, `POST /login`, `POST /logout`, `POST /forgot-password` и `POST /reset-password`. Pinia загружает текущий профиль через `GET /api/v1/user`.

**Условия/ограничения**

В этой схеме SPA и API работают на одном адресе. Укажите его в `APP_URL` вместе со схемой и портом, если он нестандартный. Если задан `SANCTUM_STATEFUL_DOMAINS`, включите в него хост SPA с портом при необходимости. Для получения ссылки настройте почту: локально можно использовать перехватчик Flock, а `MAIL_MAILER=log` записывает письмо в журнал Laravel.

## 5. Ограничить доступ к данным через политику

**Команда/действие**

Создайте [UserPolicy](app/Policies/UserPolicy.php) с методом `update`, который сравнивает текущего пользователя с владельцем профиля. В [routes/api.php](routes/api.php) примените `->can('update', 'user')` к `PATCH /api/v1/users/{user}`. В [UserController](app/Http/Controllers/Api/UserController.php) принимайте для изменения только поле `name`.

**Физический смысл**

Laravel загружает профиль по параметру маршрута и проверяет политику до выполнения действия контроллера. Неавторизованный гость получает `401`, а вошедший пользователь при попытке изменить чужой профиль — `403`.

**Краткое пояснение**

Проверка в Vue Router управляет переходами между экранами. Решение о доступе к записи принимает Laravel для каждого запроса к API.

## 6. Применить миграции, собрать и проверить приложение

**Команда/действие**

После настройки `.env` выполните:

```bash
php artisan config:clear --no-interaction
php artisan migrate --no-interaction
npm run build
vendor/bin/phpunit
```

Откройте [страницу входа в Flock](https://for-flock.test/login). Зарегистрируйте локальный тестовый аккаунт, обновите страницу профиля, измените имя и выйдите. Проверьте, что прямой переход на `/dashboard` после выхода возвращает на экран входа. Для проверки восстановления запросите письмо на адрес тестового аккаунта и откройте ссылку из локального перехватчика или журнала.

**Физический смысл**

Миграции создают недостающие таблицы, включая `users`, `sessions` и `password_reset_tokens`. Vite записывает сборку и манифест в `public/build/`. Laravel использует манифест, чтобы подключить собранные файлы.

**Краткое пояснение**

PHPUnit проверяет серверные сценарии, включая вход через сессию, сброс пароля и отказ при изменении чужого профиля. Проверка в браузере подтверждает, что страницы, cookie и переходы работают на фактическом адресе.

**Условия/ограничения**

Flock уже обслуживает сайт. Если нужен Vite с горячим обновлением, запустите `npm run dev` в отдельном терминале и открывайте тот же адрес Flock. Для полной сборки с текущей конфигурацией Vite может понадобиться доступ к Bunny Fonts. На сервере настройте корень сайта на `public/`, HTTPS и `APP_DEBUG=false`. Для миграций из скрипта развёртывания в production используйте `php artisan migrate --force --no-interaction` после проверки целевой базы.

## Заключение

Развёртывание завершено, когда приложение открывается по своему адресу, регистрация и вход работают, профиль сохраняется после перезагрузки, а ссылка из письма позволяет задать новый пароль. Тесты API должны подтверждать, что запрос без сессии получает `401`, а изменение чужого профиля — `403`.
